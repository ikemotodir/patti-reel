Why打ち合わせは、決まっていないことを決める場です

普通の映像制作で打ち合わせが要るのは、決まっていないことが多すぎるからです。尺は。予算は。修正は何回まで。いつまでに。どこまでやるのか。これを詰めるために、電話とメールが往復します。

Steps実際の工程

ご購入後、こちらで動いている中身です。緑が機械、朱が人間の担当です。

01読む 送っていただいた3項目を読みます。要約せず、そのまま制作フォルダに置きます。数字・固有名詞・価格は、あとで1文字ずつ突き合わせるためです。 人
02決める 30秒に入れられる情報は、多くて3つです。何を捨てるかを決めます。ここが仕事の本体で、機械にはできません。 人
03組む 動画をHTMLとして書きます。編集ソフトのタイムラインは触りません。文言・配色・動きが全部コードなので、直したい所だけを直せます。 人機械
04検査する 書き出す前に、機械が検査します。タイムラインを何点かで切って、その時刻の画面を1枚ずつ調べます。1つでも引っかかったら書き出しません（次の項に実際の出力があります）。 機械
05書き出す 1コマずつ描画してMP4にします。30秒の動画で15〜25秒。何度やっても同じ絵が出ます。 機械
06見て、決める 出てきた動画を人が見て、出すか直すかを決めます。ここを飛ばすことはありません。 人

Check機械が見ていること

これは実際の検査結果です。作例③（店舗・ランチの告知）を書き出す前に走らせたものを、そのまま載せています。

npx hyperframes check Lint ◇ 0 errors, 0 warnings Runtime ◇ 0 errors, 0 warnings Layout ◇ 0 issues across 9 sample(s) Motion ◇ 0 errors, 0 warnings Contrast ◇ 36/36 text checks pass WCAG AA ◇ Check passed

Layout の 9 sample(s) は、30秒のタイムラインを9点で切って、その時刻の画面を1枚ずつ調べたという意味です。

何を検出するのか

検査見ているもの
Lint構造の間違い。書体が用意されていない、時間の指定が抜けている、など
Runtime実行時のエラー。素材が読み込めていない、など
Layout文字が他の要素の下に隠れていないか。枠から文字がはみ出していないか
Motion動きの指定が壊れていないか。途中の時刻に飛んだとき絵が崩れないか
Contrast文字と背景の明るさの差。WCAG AA を全文字について測る
これが「打ち合わせなし」を支えています

「文字が被っていないか」「小さすぎないか」「読みづらい色になっていないか」は、普通は人が目で確かめるところです。だから確認の往復が生まれます。

ここでは機械が先に見てから書き出します。実際、作例①では見出しに飾り罫が31ピクセル被っていたのを機械が見つけました。目視では気づきにくい量です。

Roles機械にやらせないこと

全部を自動にはしていません。自動にすると品質が落ちる工程があるからです。

機械

  • 文字の被りの検出
  • 枠外へのはみ出しの検出
  • 配色のコントラスト測定
  • 動きの破綻の検出
  • 全フレームの描画
  • MP4への書き出し

人

  • 何を捨てるかの判断
  • 最初の3秒に置く一言
  • 数字・固有名詞の突き合わせ
  • 色と書体の方向づけ
  • 出すか直すかの最終判断
  • 受けるか断るかの判断

言い方を変えると、機械は「間違いを見つける係」で、人は「何を言うかを決める係」です。逆にすると、速いだけの動画ができます。

Limitsできないこと

この工程には向かない仕事があります。先に書いておきます。

  • 実写の撮影が要るもの — 撮影も出演も含みません。お手元の素材を使って組むことはできます
  • ナレーションを録るもの — 収録は含みません
  • 横型・正方形 — 縦（1080×1920）に特化することで、この価格と納期が成立しています
  • 何度も方向を変えたいもの — 修正は1回です。作りながら決めたい仕事には向きません
  • 権利の確認が要る素材 — 支給素材の権利処理はこちらではできません

これらが必要な場合は、正直に他所をあたってください。無理に受けて期待に届かないほうが、お互いに損です。
